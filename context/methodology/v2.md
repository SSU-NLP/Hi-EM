# v2 — STM round-clear + session-aware preload

CLI method: `hi-em-full-v2`. orchestrator `version="v2"`.

## 한 줄

**Segmenter 자체는 v1 과 동일** (`HiEMSegmenter`, Gaussian likelihood, raw sticky-CRP). 차이는 *wrapper 정책* — STM 을 매 round 끝에 비우고, 대화를 session 단위로 끊어 preload.

## v1 대비 변경

알고리즘적으로 segmentation 식은 *완전히 동일*. 변경은 **memory pipeline** 수준에서만:

| 축 | v1 | v2 |
|---|---|---|
| `round_clear_stm` | False | True (round 끝마다 STM clear → promote) |
| preload 호출 | `preload_history(flatten_history(...))` | `preload_history_sessioned(haystack_sessions, flush_stm_each=True)` |
| session 경계 활용 | 없음 (전 turn 평탄화) | session 끝마다 STM flush |

코드: `scripts/run_experiment.py` 의 `HiEMConvCache._build` method 분기.

## 동기

LoCoMo / LongMemEval 같은 **multi-session** 벤치마크에서:
- session 사이엔 시간 간격이 큼 (며칠/몇 주).
- 이전 session 의 STM 상태가 다음 session 에 새어드는 게 적절치 않음.
- session 끝에서 STM 을 clear → promote 하면, LTM 으로 의미있는 topic 만 남고 STM 은 새 session 에 깨끗한 상태로 시작.

즉 *segmentation 모델*은 그대로 두되, *memory-window* 가 session 경계를 인식하도록 함.

## Score 식 / Topic state / Update rule

→ [v1.md](v1.md) 와 동일. 여기 다시 적지 않는다.

## 하이퍼파라미터

v1 의 모든 하이퍼파라미터 + STM 관련 (round_size, stm_max_topics, stm_max_turns, promotion_threshold, importance_alpha 등) 은 wrapper 수준 hyperparameter 로 v1/v2 공통. v2 만의 새 파라미터는 *없음* — flag (`round_clear_stm`) 만.

## SEM 계승 측면

→ v1 과 동일. v2 의 추가 변경(round-clear / sessioned preload)은 SEM 본진 외 **memory architecture** 측면이라 SEM 계승 원칙과 직교.

## 알려진 한계

v1 의 한계 그대로 (Gaussian–단위구 부정합, mega-topic collapse, online MAP irreversibility, σ²₀ 튜닝 민감). v2 의 wrapper 변경은 *memory hygiene* 만 개선했고 segmentation 약점은 손대지 않음.

## 후속

- v3.x 라인은 v2 의 wrapper 정책을 *그대로* 상속하고, segmenter 만 교체. 즉 v3.1.1 / v3.2.1 / v3.3.1 모두 STM round-clear 정책에서는 v1 (=`round_clear_stm=False`) 쪽을 따름. v2 wrapper 변경은 v3 라인엔 안 옮겨짐.

## 변경 이력

- (없음) v1 과의 차이가 이미 모든 변경.
