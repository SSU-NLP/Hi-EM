# v3.3.3-4 — minimal segmenter + (topic, episode) atomic retrieval + dormant LTM safety net

CLI method: `hi-em-full-v3.3.3-4`. orchestrator `version="v3.3.3-4"`. Segmenter class: `HiEMSegmenterV333_4` (구현 2026-05-11, iter3).

## 한 줄

v3.3.3 baseline 위에 (1) restart 발화를 **보수화** 하고, (2) `(topic_id, episode_id)` 를 atomic 단위로 emit 해서 **retrieval 까지 한꺼번에** 바꾼다. v3.3.3-2/3 가 segmentation 만 만져 prefill 에 효과가 못 옮은 한계를 직접 흡수.

## 동기

- iter1 v3.3.3-2 sanity: R-mh@k -0.016 회귀, T1var 47.5 → 72.0 폭증.
- iter2 v3.3.3-3 sanity: acc -0.007 추가 회귀, R-mh@k 부분 회복하지만 baseline 0.213 못 복귀.
- 두 iter 의 공통 결론: codex 1 차 권장이었던 **`(topic, episode)` 단위 retrieval atomicity** 가 빠진 채 prototype/hysteresis 만 손대니 segmentation 의 변화가 prefill 까지 못 옮음.
- v3.3.3-4 는 segmentation 을 v3.3.3 보수화 정도로만 두고, 변화의 무게를 retrieval 쪽으로 옮긴다.

## 새 메커니즘

### 1. Segmenter (minimal)

v3.3.3 의 same-label restart 분기 위에 hysteresis 만 얹는다. prototype top-M 은 default 비활성 (`f0_proto_max=1, f0_proto_weight=0.0`).

같은 label 안에서 episode boundary 발화 조건:

$$\mathrm{boundary}_{same} = (p_{rst} > \rho_{rst}) \;\land\; (p_{rst} - p_{rep}) > m_p \;\land\; \mathrm{age}_{episode} \ge L_{\min}$$

defaults: `restart_p_threshold=0.5`, `restart_prob_margin=0.15`, `episode_min_span=8` (v3.3.3-3 의 4 → 상향, RNN noise burst 흡수폭 확장).

`assign(s)` return 이 `(topic_id, is_boundary, episode_id)` **3-tuple** — orchestrator 가 STM/LTM 에 episode_id 를 같이 저장.

### 2. `(topic_id, episode_id)` atomic retrieval (importance-only, 2026-05-11 재설계)

> ⚠️ **2026-05-11 재설계**: query embedding cosine matching (RAG-style) 영구 폐기.
> [`CLAUDE.md` § "Retrieval 은 importance score 만으로 한다"](../../CLAUDE.md) 참조.

`HiEMConv.eval_query` 의 prefill = **STM 의 모든 turn 을 turn_id 오름차순으로 dump**. 이게 전부다.

근거:
- STM membership 자체가 SEM importance gate. round-end promotion + eviction 으로 이미 결정됨.
- query time 에 다시 importance lookup / scoring 하는 것은 redundant. STM = "지금 working memory 에 있어야 하는 것".
- (topic, episode) atomicity 는 STM 자체의 atomicity (topic 단위 promote / evict) 가 자연 보장.

코드: `HiEM._importance_prefill()` (`src/hi_em/orchestrator.py:343`):
```python
def _importance_prefill(self) -> list[dict[str, Any]]:
    if self._stm is None:
        return []
    turns = list(self._stm.all_turns())
    turns.sort(key=lambda t: int(t.get("turn_id", 0)))
    return turns
```

`(topic_id, episode_id)` 필드는 segmenter 가 emit 하지만, retrieval 단계에서는 **선택 / 정렬 키로 사용 안 함**. 진단 / 향후 episode-aware promotion policy 용 보존.

폐기된 메커니즘:
- ~~`max cos(q, s_i)` episode rerank~~ — query-aware, RAG-style. CLAUDE.md 규칙 위반.
- ~~`b·S_topic + e·S_episode − g·z̄PE − r·recency` weighted formula~~ — 본래 미구현 (코드와 문서 불일치) 이었고 재설계로 영구 제거.
- ~~`dormant_ltm_top_n` cosine top-N fallback~~ — STM 못 들어간 LTM topic 의 turn 을 query cosine 으로 끌어옴. CLAUDE.md 규칙 위반.

**대안**: dormant evidence 회수는 **promotion policy 책임**. importance policy 자체 강화 (별도 작업) 또는 promotion threshold calibration (default 0.3 유지).

### 2b. Importance policy v2 (2026-05-11 추가)

cosine 폐기 후 dormant evidence 회수 위해 `compute_importance()` 확장:

$$raw_I(t) = w_1 s_{count} + w_2 s_{freq} + w_3 s_{recency} + w_4 s_{nbr} + w_5 s_{PE} + w_6 s_{boundary} + w_7 s_{span}$$

새 SEM-internal salience 항 3 개:
- **PE salience** ($s_5$): topic 의 누적 prediction error (mean + max 혼합). SEM2 PE 직접 연결.
- **Boundary frequency** ($s_6$): topic 안 episode count. SEM2 event dynamics.
- **Persistence span** ($s_7$): 첫 등장 ~ 최근 등장 span. scene dynamics 장기 흔적.

기존 항도 보강: $s_{count}$ 에 cap (n_cap=30) 적용 → 대형 topic peak anchor 약화.

defaults: `(w1..w7) = (0.70, 0.60, 0.45, 0.35, 0.90, 0.70, 0.25)`, `n_cap=30, pe_ref=1.0, boundary_ref=3.0, span_ref=12.0`.

v3.3.3-4 orchestrator 가 자동으로 `importance_version="v2"` + 7-tuple weights 적용. v1 백워드 compat 유지.

자세한 정당화 + 검증 → decision-log 2026-05-11 "Importance policy v2" entry 참조.

### 3. Promotion threshold 인하 (유지)

`promotion_threshold = 0.3` (default 0.5). evidence-bearing topic 가 score 낮아 STM 못 들어가는 경우를 줄임. 단 dormant audit 결과 (top_ev_topic_promoted=0.31) 보면 threshold 인하 자체로는 충분치 않음 — importance policy 보강 별도 작업으로 처리.

### 4. Dormant LTM safety net (~~폐기, 2026-05-11~~)

> 폐기: `_importance_prefill()` 에서 dormant LTM cosine top-N 로직 제거.
> 사유: CLAUDE.md "Retrieval 은 importance score 만으로 한다" 규칙 위반.
>
> 이 메커니즘이 v3.3.3-4 iter1 sanity 의 H@k 폭증 (0.32 → 0.64) 의 주된 원인이었음. 폐기 후 retrieval recall 은 baseline 수준 회복 예상. acc 회복은 importance policy 강화 (별도 작업) 가 담당.

## SEM 계승 정당화

1. **`(topic, episode)` atomicity** = SEM2 `new_token()` 의 직접 대응. 한 token = 한 episode = 한 prediction-error 가 같이 묶이는 단위. SEM 철학에 충실.
2. **Episode rerank scoring**: SEM 외 (QA readout 정책) 이지만 비학습 + 비파괴 — 단순 weighted sum. SEM 의 sCRP / Bayes / local MAP 와 직교.
3. **Dormant LTM safety net**: SEM 외 (retrieval safety). 학습 없음, importance score 정책의 단순 미스를 backstop. promotion threshold 와 결합되어 evidence 누락 줄임.
4. **Hysteresis**: v3.3.3-3 동일 (SEM2 `restart > repeat` 의 noise threshold 해석).
5. **decision-log entry**: 2026-05-10 v3.3.3-4 iter3 design.

## 알려진 한계

1. **HP default 미검증**: `episode_top_k=3, dormant_ltm_top_n=8, b=0.10, e=0.35, g=0.05, r=0.03, promotion=0.3` 는 codex 권장 + 1 차 추정. grid 검증 미진행. sweep 필요 (sanity 통과 후).
2. **Token budget 와 episode atomicity 의 충돌 가능성**: episode 가 통째로 들어가야 atomic 인데, token budget 으로 turn 단위 cut 을 하는 순간 atomicity 가 깨짐. 현재는 budget 안에서 잘라 사용하는 fallback. 향후 "budget 초과 시 episode 단위 drop" 으로 강화 검토.
3. **Dormant LTM 의 importance score 의존**: LTM 에서 dormant topic 을 cosine top-N 으로 뽑지만, LTM 자체의 표본 분포는 promotion 이력에 종속. 정말로 backstop 이 되는지는 audit metric 으로 직접 확인 (`dormant_ev_rate`, `top_ev_topic_promoted`).
4. **Episode rerank 의 query-side feature 부재**: query embedding 만 사용. prediction-error / topic-prior 같은 query-time SEM signal 미통합. 향후 PE-aware rerank 검토.
5. **Diagnostic counter 미연결**: segmenter 의 `_n_*` counters (assigns, label_change, repeat/restart wins, hysteresis_blocked) 는 인스턴스에 살아있지만 round summary 에 emit 안 되고 있음. iter1 sanity 후 eval_logging 에 hook.
