## 새 메커니즘

### Prototype f0

각 topic $k$ 가 boundary-start embedding 의 top-M unit-norm prototype list $P_k$ 를 유지 (default `f0_proto_max=4`). 새 boundary-start sample $s$ 가 들어오면:

- `len(P_k) < M`: append.
- `len(P_k) == M`: 가장 cosine 유사한 prototype 과 평균 후 재정규화 (mass conservation).

$$f0\_score(k, s) = \max_{p \in P_k} \cos(p, s)$$

cold-start (`f0_count < f0_min_starts`) 에는 v3.3.3 와 동일하게 topic centroid `mu` fallback.

### Posterior-odds restart

기존 $S^{rep}_k, S^{rst}_k$ 식은 v3.3.3 와 동일. 단 `k = k_{prev}` 에서 `S = max(rep, rst)` 후의 boundary 판정을 hard PE gate 대신 softmax posterior 로:

$$p_{rst} = \frac{\exp S^{rst}_{k_{prev}}}{\exp S^{rst}_{k_{prev}} + \exp S^{rep}_{k_{prev}}}$$

$$boundary_{same} = (p_{rst} > \rho_{rst})$$

default `restart_p_threshold=0.35` (낮춰 restart 활성화 의도). `restart_pe_min` (default `0.0`) 은 옵션 floor.

## SEM 계승 정당화

- prototype top-M f0 는 **새 메커니즘**. SEM2 는 단일 f0 centroid (`update_f0(x_curr)`).
  1. **SEM 에 왜 없는가**: SEM2 자극은 controlled VAE 영상이라 event-시작 패턴이 단봉 분포. 대화 topic 은 같은 label 안에서도 재방문 시작 패턴이 다양하므로 multi-prototype 이 필요할 수 있음.
  2. **충돌**: SEM2 `new_token()` 의 정신은 살아 있음 (label 유지 + episode 분리). prototype list 가 그 token 의 다양한 시작 자세를 표현. sCRP / Bayes / local MAP 와 직교.
  3. **decision-log entry**: 2026-05-10 v3.3.3-2 첫 sanity.

- posterior odds 는 SEM2 `restart > repeat` 조건의 cosine-환경 재해석. SEM2 는 Gaussian likelihood 직접 비교; posterior softmax 는 그 비교의 numerically stable 형태이며 cosine surrogate 에서도 의미 보존.

## iter2 재설계 방향 (v3.3.3-3, 진행 예정)

codex 재설계 (`agentId: a4f3e7b1468a14b3f`) 권장:

1. **restart 보수화**: `restart_p_threshold=0.5` 로 상향 + `restart_prob_margin=0.15` 추가 + `episode_min_span=4` (직전 restart 후 최소 turn 간격).

3. **episode atomicity 를 retrieval layer 에서 직접 구현** (iter1 미구현 핵심): segmenter 가 `(topic_id, episode_id)` 발급 + retrieval 시 episode 단위 rerank. `R(i) = a·cos(q,s_i) + b·S_topic + e·S_episode - g·zPE - r·recency` 형식.

이 셋이 R-mh@k 회복 + T1var 안정 + acc 향상 가능성 동시 확보 의도.

## 알려진 한계

1. **R-mh@k 회귀 원인 미특정**: 가설 (restart 과다, prototype dilution) 은 설계 직관. 데이터 검증 안 됨. iter2 에서 restart 발화 횟수 logging + `restart_p_threshold ∈ {0.35, 0.5, 0.7}` ablation 으로 격리 검증 필요.
2. **T1var 폭증 (47.5→72.0)**: RNN init noise 가 prototype f0 + posterior odds 에 증폭됨. iter2 설계 (hysteresis + minimum-span guard) 가 이를 흡수해야.
3. **acc 자체 향상 0**: 의도한 같은-label 재방문 효과가 prefill 변화로는 안 옴 — 즉 (topic, episode) atomic retrieval 같은 readout 측 변경이 동반돼야 acc 가 움직일 가능성. iter2 핵심 의제.
4. **prototype top-M `max`** 의 seed 민감도: 가장 가까운 prototype 1 개로만 평가 → init randomness 가 직접 score 에 흘러감. softening (logmeanexp) 으로 완화 예정.
