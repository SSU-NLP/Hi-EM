# v3.3.3 / v3.3.4 LoCoMo sweep plan

목표: 기존 RAG 계열 3개와 Hi-EM v3.3.2 / v3.3.3 / v3.3.4 를 같은 LoCoMo full setting 에서 비교한다.

## Full LoCoMo 6-method sweep

`scripts/experiment.py` canonical 형식:

```bash
uv run python scripts/experiment.py \
  --name 2026-05-09_v333_v334_full_6method \
  --benchmark locomo \
  --data benchmarks/locomo/data/locomo10.json \
  --workers 100 --no-thinking \
  --method "rag:rag" \
  --method "rag-observation:rag_observation" \
  --method "rag-summary:rag_summary" \
  --method "hi-em-full-v3.3.2:v332_best@cos_threshold=0.9,alpha=100,beta=0.25,pe_threshold=0.5,rnn_train_steps=3" \
  --method "hi-em-full-v3.3.3:v333_f0@cos_threshold=0.9,alpha=100,beta=0.25,pe_threshold=0.5,rnn_train_steps=3,restart_pe_threshold=0.5,restart_margin=0.0" \
  --method "hi-em-full-v3.3.4:v334_var@cos_threshold=0.9,alpha=100,beta=0.25,rnn_train_steps=3,pe_var_decay=0.95,pe_var_min_samples=5,pe_var_sigma0_sq=0.04,hard_pe_fallback=false"
```

주의: 현재 코드에는 `hi-em-full-v3.3.3` / `hi-em-full-v3.3.4` method mapping 이 아직 없으므로, 위 명령은 구현 후 실행한다.

## 예상 wall time

기준: v3.3.2 full LoCoMo 1 method ≈ 58분.

추정:

| method | 예상 |
|---|---:|
| `rag` | 20~35분 |
| `rag-observation` | 20~35분 |
| `rag-summary` | 20~35분 |
| `hi-em-full-v3.3.2` | 약 58분 |
| `hi-em-full-v3.3.3` | 60~65분 |
| `hi-em-full-v3.3.4` | 60~65분 |

단순 합산: 약 4.0~4.9시간. `scripts/experiment.py` 가 method 를 순차 실행한다면 이 범위를 예상한다. 같은 LLM endpoint 에 충분한 여유가 있고 method 병렬 실행을 별도 session 으로 나누면 wall time 은 줄 수 있지만, rate limit / GPU contention 때문에 canonical run 은 순차 실행을 기본으로 둔다.

## 비교 기준

primary:

- overall accuracy
- qtype별 accuracy: `mh`, `sh`, `tr`, `adv`, `od`
- STM topic 통계: `T1μ/T2μ/T3μ`, `T1max/T2max/T1var`, `n_topics`
- generation latency p50, wall time

repeat-vs-restart 에 민감할 가능성이 큰 축:

- `temporal reasoning (tr)`: 같은 인물 / 주제로 돌아오지만 시점이 다른 episode 를 구분해야 할 수 있다. v3.3.3 의 same-label restart 가 유리할 후보.
- `multi-hop (mh)`: 한 답이 같은 topic 의 여러 episode-start 정보를 연결해야 하면, restart boundary 가 STM/LTM chunk 구조를 개선할 수 있다.
- `adversarial (adv)`: 이전 정보와 새 정보가 같은 label 아래 충돌할 때 restart 가 낡은 episode 와 새 episode 를 분리해 도움될 수 있다.

v3.3.4 에 민감할 가능성이 큰 축:

- `open-domain / other (od)`: topic 폭이 넓어 global PE threshold 가 과분할할 수 있는 질문군이면 variance calibration 이 유리할 수 있다.
- `single-hop (sh)`: 좁은 factual topic 에서 작은 PE spike 를 민감하게 잡으면 retrieval precision 이 좋아질 수 있다.

판정:

- v3.3.3 이 v3.3.2 대비 `tr` 또는 `mh` 를 올리면서 `n_topics` 폭증이 없으면 repeat-vs-restart 복원 성공.
- v3.3.4 가 v3.3.2 대비 overall 또는 `od` 를 올리고 `T1max/T1var` 를 낮추면 global threshold calibration 성공.
- v3.3.4 의 이득이 작거나 topic 통계가 불안정하면 SEM 계승 부담 때문에 default 승격하지 않는다.

## 후속 ablation

full 6-method 결과 후 필요한 경우에만 실행한다.

  --name 2026-05-09_v333_v334_ablation \
  --benchmark locomo \
  --data benchmarks/locomo/data/locomo10.json \
  --limit 300 --stratify \
  --workers 100 --no-thinking \
