## 구현 단계

1. `TopicV333RNNF0` 설계
   - v3.3.1 topic state 를 유지: centroid, count, per-topic hidden state, cached prediction.
   - f0 state 추가: episode-start embedding 의 normalized running mean.
   - `f0_score(s)` 는 sample 부족 시 centroid 또는 current embedding-independent fallback 사용.
2. `HiEMSegmenterV333.assign()`
   - active prior 계산은 v3.3.2 와 동일.
   - 모든 topic 의 ordinary score 계산.
   - $k_{\text{prev}}$ 가 있으면 repeat score 와 restart score 를 별도 계산.
   - MAP 에 들어가는 $S_{k_{\text{prev}}}$ 는 `max(repeat, restart)`.
   - chosen topic 이 previous 와 같고 restart 가 repeat 를 margin 이상 이기면 boundary true.
3. update 순서
   - boundary true 이면 해당 topic 의 f0 centroid 를 현재 embedding 으로 update 후 RNN token reset / hidden handling.
   - repeat 이면 기존 v3.3.2 update.
   - 새 topic 이면 f0 centroid 와 centroid 모두 첫 sample 로 초기화.
4. `predict_topic()`
   - read-only 이므로 f0 / restart score 를 계산하되 state update 없음.
   - query 에 대해 boundary 를 반환하지 않는 기존 API 를 유지.

## 테스트 계획

`tests/test_v333_f0.py`

1. `test_same_topic_restart_can_mark_boundary`
   - $k_{\text{prev}}$ 가 MAP winner 이지만 restart score 가 repeat 보다 크면 `(same_k, True)` 반환.
2. `test_same_topic_repeat_no_boundary`
   - repeat score 가 크면 `(same_k, False)` 반환.
3. `test_restart_does_not_create_new_topic`
   - same-label restart 는 topic count 를 늘리지 않고 f0 state 만 업데이트.
4. `test_restart_margin_blocks_tie_noise`
   - `restart_margin` 미만 차이는 repeat 로 처리.
5. `test_v333_reduces_to_v332_when_restart_disabled`
   - `restart_pe_threshold=2.0` 또는 `f0_min_starts` 를 매우 크게 두면 v3.3.2 와 동일 assignment.
6. `test_predict_topic_is_read_only_with_f0_scores`
   - counts, topics, f0_count, prev_k 변경 없음.
